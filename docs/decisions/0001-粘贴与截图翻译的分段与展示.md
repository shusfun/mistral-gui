# 0001 粘贴与截图翻译先重建段落，结果以浮层段落对照展示

## 背景

翻译工作台的粘贴翻译和截图翻译原来按每个换行逐行翻译：

- `internal/app/translate.go` 的 `splitDesktopParagraphs` 遇到每个 `\n` 都会切开；
- OCR 只保留每行的文字和置信度（`OCRLine` 只有 `text`、`score`），每行再用 `\n` 拼起来。

从 PDF 或截图得到的文字，句子中间常有硬换行，逐行翻译会把一句话拆成几段残句。而且 OCR 丢掉了位置信息，没有办法判断哪些行属于同一段，也分不清多栏排版。

## 决定

- **粘贴文字**：按轻译仓库 `docs/decisions/0001-段落重建规则共享.md` 中的共享规则重建段落后再翻译。参数来自同步过来的共享规则文件，与轻译使用同一组样例测试。
- **截图和粘贴图片**：
  - OCR 结果保留每行的位置框；
  - 先按栏分组，再按阅读顺序排序；
  - 根据行距突变、首行缩进、左边界变化判断段落；
  - 每段内部再套用共享的合并规则。
- **默认展示：浮层按段对照**。选区旁的浮层逐段显示：原文用灰色并保留原来的换行，紧跟其下是这一段的译文。可以切换为「只看译文」，方便复制。「贴回原图」（把译文覆盖到原图对应区域）作为可选模式。
- 合并后的原文用户可以看到并修改，也可以切换为「按原换行逐行翻译」。
- 原文和译文只留在当前页面的内存里，不写进 URL、浏览器历史或日志。

## 考虑过的方案

- **继续逐行翻译**：残句翻译质量差，也浪费请求。放弃。
- **以「贴回原图」为默认展示**：更像拍照翻译，但小字号、密集排版时译文容易遮挡或溢出，也不方便复制和对照。所以作为可选模式。
- **完全照搬百度翻译的合并方式**：百度会把列表项并成一行。所以在共享规则中加入列表、标题、代码的例外。
- **像百度那样把原文放进页面 URL**：百度在打开段落对照时会把整段原文写进地址栏，原文会留在浏览器历史里。放弃。

## 影响

- OCR 接口需要返回位置框，`OCRLine` 结构和 OCR worker 的输出都要扩展。
- 翻译响应要能按段落返回原文和译文的对应关系，前端浮层和翻译工作台据此按段渲染。
- 段落重建会改变送去翻译的文本，所以合并后的段落数量和长度上限要重新核对（当前上限是 128 段）。
- `translation.stage` 中可以记录重建前的行数和重建后的段落数，便于排查合并是否符合预期。

## 依据

- 2026-11-18 与用户的讨论。默认处理方式选择「智能合并段落也参考百度呀」，截图展示选择「浮层段落对照」。
- 同日实测百度翻译文本翻译页：段内合并、空行分段、提供段落对照，但列表项被合并成一行；开启段落对照后原文出现在地址栏的 `query` 参数中。
